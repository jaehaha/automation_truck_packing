# mp: 적재 모션 플래너

`../sim_final` 의 경로 계획기(`Stacker`)를 이 폴더로 옮긴 것이다.
투입 위치의 상자를 윗면으로 흡착해, 이미 놓인 상자를 피해 지정한 자리에 놓는 **관절 경로**를 만든다.

- 입력: 상자 종류, 놓을 중심 좌표, 놓인 방향(x·y·z 길이)
- 출력: 경유 자세 목록. 한 자세는 `[레일(m), 관절1..6(rad)]`
- 운동학 계획이다. 경로를 만들고 MuJoCo 로 충돌만 검사한다. 무게, 흡착력, 놓은 뒤 무너짐은 계산하지 않는다.

**어디에 놓을지는 여기서 정하지 않는다.** 자리는 Packing Model(`manibox_packing_handoff`)이 정하고, 이 폴더는 그 자리까지 가는 길만 만든다 (`../pipeline/mp.md`).

## 파일

| 파일 | 내용 |
|---|---|
| `stacking.py` | 계획기 `Stacker`. `sim_final/scripts/stacking.py` 와 같고 `ROOT` 경로 한 줄만 다르다 |
| `plan_job.py` | 작업 파일(JSON) → 경로(JSON). 뷰어 재생, MP4 저장 |
| `example_job.json` | 작업 파일 예시 (상자 5개) |
| `model/manibox_modified.xml` | 프레임 + 레일 + 거꾸로 달린 Piper + 흡착 공구 모델 |
| `assets/` | 모델이 쓰는 메시 (프레임, 캐리지, Piper, 흡착 공구) |

## 실행

```bash
cd mp
uv run python plan_job.py example_job.json --out plan.json   # 계획만
uv run python plan_job.py example_job.json --view            # 뷰어에서 재생
uv run python plan_job.py example_job.json --mp4 out.mp4     # 영상으로 저장
```

예시 5개는 상자당 0.6 ~ 3.4 초에 모두 계획된다.

### 작업 파일

놓는 순서대로 적은 목록이다.

```json
[{"id": "a", "type": 6, "center": [1.45, 0.110, 0.123], "size_xyz": [0.10, 0.16, 0.16]}]
```

| 키 | 뜻 |
|---|---|
| `type` | 상자 종류 1 ~ 6 (아래 표) |
| `center` | 놓인 상자의 중심 (m) |
| `size_xyz` | 놓인 상자의 x, y, z 방향 길이 (m). 상자 치수의 순열 |
| `frame` | `"world"`(기본) 또는 `"robot"` |
| `pick_xy` | 집는 위치 (월드 x, y). 없으면 (0.29, 0.28) |
| `grip` | 흡착점이 윗면 중심에서 벗어난 거리 (가로, 세로) m |
| `mode` | `"top"` / `"side"`. 없으면 `size_xyz` 로 정한다 |

### 결과 파일

상자마다 `{id, ok, reason, mode, approach, carry, retreat}`.

| 구간 | 내용 | 흡착 |
|---|---|---|
| `approach` | 지금 자세 → 투입 위치 위 → 윗면에 닿기 | 끝에서 켬 |
| `carry` | 띄우기 → 들어올리기 → 세우기 → 돌리기 → 이송 → 내리기 → 밀어 넣기 → 놓기 | 끝에서 끔 |
| `retreat` | 온 길을 거꾸로 빈손으로 | 끔 |

실패한 상자는 `ok: false` 와 이유만 남기고 건너뛴다.

## 코드에서 쓰기

```python
from stacking import Stacker

s = Stacker([6, 6, 5])                       # 이번 작업의 상자 종류 (놓는 순서)
plan = s.plan(0, center=(1.45, 0.11, 0.123), size_xyz=(0.10, 0.16, 0.16), frame="world")
if plan.ok:
    # plan.approach / plan.carry / plan.retreat 를 실행
    s.commit(plan)                           # 놓인 것으로 확정 -> 다음 상자의 장애물
else:
    print(plan.reason)
```

`plan()` 은 장면을 바꾸지 않는다. `commit()` 을 불러야 그 상자가 장애물이 되고, 다음 계획의 출발 자세가 후퇴 끝 자세로 바뀐다.

## 좌표와 상자

- **월드**: 프레임 모서리 바닥이 원점. x = 레일 방향(문 → 정면 벽), z = 위.
- **로봇**: 레일 0 일 때의 팔 베이스가 원점. 로봇 = 월드 − (0.700, 0.280, 0.672).
- 레일 범위 −0.49 ~ +0.51 m, 바닥판 윗면 월드 z = 0.043 m.
- 공구: 플랜지에서 흡착컵 끝까지 147.5 mm (컵 길이 25 mm 는 가정값).

| 종류 | 가로 × 세로 × 높이 (cm) |
|---|---|
| 1 | 8 × 8 × 8 |
| 2 | 8 × 8 × 10 |
| 3 | 16 × 8 × 8 |
| 4 | 16 × 8 × 10 |
| 5 | 16 × 8 × 12 |
| 6 | 16 × 16 × 10 |

투입 위치에서 상자는 높이가 위, 가로가 y 방향이다. 흡착면은 항상 가로 × 세로 면이다.

놓는 방식 두 가지:
- **top**: 흡착면이 위. 공구가 수직이라 낮은 곳만 닿는다.
- **side**: 흡착면이 문 쪽(−x). 상자의 높이 변이 x 방향으로 눕는다. 공구가 수평.

상자 높이가 y 방향이 되는 배치는 지원하지 않는다.

## 동작 순서

1. **접근**: 빈손으로 투입 위치 위로 간다. 직접 못 가면 대기 자세를 거친다.
2. **집기**: 공구를 수직 아래로 두고 윗면에 닿는다.
3. **띄우기**: 5 mm 올린다. 수직으로 못 올리면 5° 기울이면서 10 mm 올린다.
4. **들어올리기**: 수직으로 올릴 수 있는 데까지.
5. **세우기**: 공구를 5° 씩 수평(+x)으로. 단계마다 "올리기 / 앞으로 밀기" 후보 중 충돌 없는 첫 번째를 쓴다.
6. **돌리기**: 공구축 둘레로 10° 씩 돌려 상자의 세울 변을 맞춘다.
7. **이송**: 팔 자세를 놓는 쪽 자세로 만든 뒤 레일만 민다. 막히면 직선 이동으로 바꾼다.
8. **내리기**: side 는 자리보다 15 mm 문 쪽에서 내려와 받침 위 5 mm 에서 멈춘다.
9. **밀어 넣기**: +x 로 15 mm.
10. **놓기**: 5 mm 내려 얹는다.
11. **후퇴**: 온 길을 거꾸로.

집는 쪽(2 ~ 5)과 놓는 쪽(10 ~ 8 을 거꾸로)을 각각 "그 자리에서 이송 자세까지 올라가는 경로"로 만들고 가운데를 6, 7 로 잇는다.
공구 x축을 집을 때 4방향, 놓을 때 2방향으로 바꿔 가며 처음 되는 조합을 쓴다.

## 충돌 규칙

| 규칙 | 값 |
|---|---|
| 든 상자·놓인 상자가 낀 접촉은 이 간격 미만이면 충돌 | 3 mm (`CLEAR`) |
| 맞닿음 허용 깊이 (집는 순간·놓는 순간의 한 구간만) | 1.5 mm (`TOL`) |
| 경유 자세 사이를 나눠 검사하는 간격 | 관절 0.03 rad, 레일 1 cm |
| 공구 끝 최고 높이 | 월드 z 0.47 m (`ZMAX`) |
| 놓은 뒤 | 방금 놓은 상자를 장애물로 넣고 후퇴 경로를 다시 검사 |

든 상자는 실제 크기로 공구에 붙여 검사한다. `grip` 을 주면 그만큼 치우쳐 붙인다.
팔·공구는 메시의 볼록 껍질, 프레임·캐리지는 상자 근사, 상자는 직육면체다.

## 확인한 것

- `example_job.json` 5개를 이 폴더의 계획기와 `sim_final` 원본으로 각각 계획해 경유 자세를 비교했다. 개수가 같고 값 차이는 5e-7 이하(저장할 때의 반올림)다.
- MP4 저장까지 실행했다. 뷰어 재생(`--view`)은 창이 필요해 실행해 보지 않았다.

## 한계

- 정해진 순서로 찾는다. 실패는 "이 방법으로는 못 찾았다"는 뜻이고 경로가 없다는 증명이 아니다.
- 윗면 집기는 중심선(월드 y = 0.28) 위의 투입 위치에서만 된다.
- 월드 x < 0.70 m 쪽 자리는 거의 실패한다. 집어서 세우는 동작이 그 공간을 쓴다.
- 상자의 작은 회전(yaw) 오차는 받지 않는다. 공구 방향은 90° 단위다.
- 상자 종류는 `stacking.BOXES` 6종뿐이다. 다른 치수는 표에 추가해야 한다.
- 속도·가속도는 다루지 않는다. 경유 자세를 시간에 따라 나누는 것은 실행기의 일이다.
- `sim_final` 의 모델이나 `stacking.py` 가 바뀌면 이 폴더는 따라 바뀌지 않는다. 다시 복사해야 한다.
