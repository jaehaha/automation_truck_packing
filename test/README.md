# test: 네 단계 방식 모션플래닝 시험

`../pipeline/mp.md` 의 방식(집기 → 이송 자세 → 레일 이동 → 놓기)을 구현하고,
handoff 예시 계획(`moves_big_104.json`, 놓기 102개)을 전부 돌려 성공률을 본다.

## 실행

```bash
cd test
uv run --project ../mp python run.py                   # 전체 검사 (약 30초, 두 번째부터 3초)
uv run --project ../mp python run.py --view            # 검사 뒤 뷰어에서 전체 재생 (1배속 약 12분)
uv run --project ../mp python run.py --view --speed 4  # 4배 빠르게
uv run --project ../mp python run.py --view --box 37   # 37번째 놓기만 반복 재생 (앞 상자는 이미 놓인 상태)
```

결과는 화면과 `result.json` 에 나온다. 창을 닫으면 끝난다.

| 항목 | 값 |
|---|---|
| 전체 놓기 | 102개 |
| 투입 구역(문 쪽 면이 월드 x < 0.70 m)이라 제외 | 14개 |
| 시도 | 88개 |
| **성공** | **85개 (96.6%)** |
| 실패 | 3개 |

실패 3개:

| 번호 | 자리 | 이유 |
|---|---|---|
| 74 | x 0.787, z 0.123 (문 쪽 경계, 바닥 단) | 레일이 범위 끝(−0.49 m)에 걸린다 |
| 81, 91 | z 0.563 (가장 높은 단) | 이송 높이(0.47 m)보다 높은 자리다. 팔을 놓는 높이로 옮길 때 든 상자가 투입 구역 밖으로 약 8 cm 나와 앞줄 상자에 걸린다 |

성공한 85개를 새 장면에서 관절 0.01 rad 간격(147,549 프레임)으로 다시 재생해 접촉을 따로 계산했다.
가장 깊은 접촉은 1.25 mm 로 허용 범위(1.5 mm) 안이다.

쓰인 후보: 85개 중 82개가 x 와 무관한 틀(레일 값만 옮김)로 통과했고, 3개는 그 자리 기준으로 계산한 마지막 후보를 썼다.
카메라 받침 방향은 모두 옆(+y 또는 −y)이었다. "위" 는 한 번도 쓰이지 않았다.

## 파일

| 파일 | 내용 |
|---|---|
| `rules.py` | **편집하는 곳.** 투입 구역 경계, 추가 상자 종류, 놓는 동작 후보와 그 순서 |
| `sequence.py` | 네 단계 구현. 빈 장면에서 틀을 계산해 저장하고, 실행 전에 지금 장면에서 검사 |
| `run.py` | 예시 계획 전체 검사, 뷰어 재생 |
| `cache/` | 저장해 둔 틀. `rules.py` 나 코드, 모델이 바뀌면 자동으로 다시 계산 |

역기구학과 충돌 검사는 `../mp/stacking.py` 를 그대로 쓴다.

## 동작 방식

- **틀**: 집기부터 놓기까지의 경유 자세를 빈 장면에서 한 번 계산해 둔 것. (상자 종류, 긴 변 방향, y, z, 후보)마다 하나다.
- **실행 전 검사**: 틀의 놓는 쪽 자세에서 레일 값만 자리의 x 만큼 옮기고, 지금 쌓인 상자와 부딪히는지 단계별로 검사한다. 경로를 새로 찾지 않는다.
- **후보**: `rules.PLACE_CANDIDATES` 를 위에서부터 시도해 처음 통과한 것을 쓴다. 다 안 되면 그 상자는 실패이고, 가장 멀리 간 단계가 이유로 남는다.

## 규칙을 고치는 방법

1. `run.py` 결과에서 실패한 번호와 이유를 본다.
2. `rules.py` 를 고친다. 상황별로 후보 순서를 바꾸려면 `place_candidates(box)` 에 조건을 적는다.
3. `run.py` 를 다시 돌려 성공 수가 어떻게 바뀌었는지 본다.
4. 바뀐 상자를 `--view --box 번호` 로 확인한다.

## 알아 둘 것

- 예시 계획 하나로 잰 성공률이다. 다른 계획에서는 다를 수 있다.
- 실패하거나 제외한 상자는 장면에 없는 것으로 두고 다음 상자를 계속한다. 실제로는 그 위에 놓일 상자가 받침을 잃는다. Packing Model 에 `reject()` 로 잇는 일은 아직 하지 않았다.
- 투입 위치는 `sim_final` 의 값(월드 0.29, 0.28)이고 오차는 넣지 않았다.
- 버퍼 칸으로 옮기는 이동(예시에 1개)은 다루지 않는다.
- `sim_final` 에 없던 160 × 160 × 80 상자를 종류 7 로 더했다 (`rules.EXTRA_BOXES`).
- 무게, 흡착력, 속도 한계는 계산하지 않는다.
