# ManiBox 상자 적재: 모션 플래닝 전달 설명서 (최종 도면, 목록 방식)

적재 목록(상자 id, 배송 지점, 종류)을 넣으면 **투입 순서**와 **로봇 이동 목록**이 나온다.
상자마다 이동이 하나다: 투입 칸에서 윗면을 집어 → 돌려서 → 입구 쪽에서 안쪽(+x)으로 밀어 넣는다.
큰 상자 모드는 팔이 밀어 넣기로 못 닿는 입구 쪽 바닥층에 한해 **위에서 내려놓기**(돌리지 않고 수직으로 내려놓기)도 쓴다(4절).
모션 플래닝은 이 점들 사이 경로만 만들면 된다. 이동 순서가 곧 실행 순서이고, 투입 칸에 상자를 넣는 순서다.

공간은 경인 최종 도면(`ManiBox_Floor_Panels_Dimensions.pdf`)을 따른다. 평면도: `rig_plan_final.png`.

## 1. 실행

```bash
uv sync                                                    # 처음 한 번 (Python 3.12, mujoco, numpy, gymnasium)
uv run python plan_moves.py --mode big --manifest examples/list/manifest_big.json --motion --out moves.json
#   -> moves.json (전체) + moves.csv (한 줄 = 이동 하나). 16번 계획해 가장 많이 실은 것을 쓴다 (80개 목록 약 3분)
uv run python check_plan.py moves.json                     # 이 저장소 로봇 모델로 모든 이동을 처음부터 다시 검사
MUJOCO_GL=egl uv run --with "imageio[ffmpeg]" python plan_moves.py --mode big --manifest 목록.json --motion --video load.mp4
```

- `--mode big`: 큰 상자 5종(`policy_big_list.npz`), 밀어 넣기 + 위에서 내려놓기. 최종 기준 모드다.
- `--mode stable`: pack_env 기본 상자 5종(`policy_list.npz`), 밀어 넣기만(내려놓기는 학습하지 않았다).
- 적재 목록은 JSON `{"boxes": [{"id": "P001", "stop": 4, "type": 1}, ...]}` 또는 CSV(`id,stop,type` 또는 `id,stop,L,W,H`)다.
  - 지점 1이 먼저 내린다.
  - 목록 순서는 상관없다. 투입 순서는 프로그램이 정한다.
- `--plans N`: 계획 횟수(기본 16). 1이면 학습한 모델 그대로 한 번.

## 2. 어떻게 정하나

- 학습한 모델이 매번 남은 목록 전체(지점별·종류별 남은 수)와 지금 쌓인 모양을 보고, **다음에 넣을 상자와 놓을 자리를 같이** 고른다.
- 지점은 나중에 내릴 곳부터 넣는다. 입구 쪽에서 밀어 넣으니 먼저 내릴 상자가 늘 입구 쪽이나 위에 와서 하차 순서가 저절로 맞는다.
- 놓는 방법도 모델이 고른다(큰 상자): 입구 쪽에서 밀어 넣기(`front`) 또는 위에서 내려놓기(`top`).
- 자리마다 안정성(물리 시뮬레이션)과 로봇 팔 검사(IK·충돌)를 하고, 안 되면 다음 순위를 쓴다.
- 16번 계획한다(첫 번째는 모델 그대로, 나머지는 모델의 확률대로 조금씩 다르게). 그중 가장 많이 실은 것을 내보낸다.

## 3. 공간과 좌표 (월드 = 도면 좌표, 원점 = 입구 쪽 프레임 모서리)

| 항목 | 값 |
|---|---|
| 프레임 | 1600 × 560 × 780 mm. 입구 X0, 뒤 프레임 X1600 |
| 바닥판 | X41 ~ X1519 (1478 × 558, 두께 12) → 바닥 높이 z 0.052 m |
| 적재 구역 | X41 ~ X1241 (깊이 1200), 폭 480 (y 0.04 ~ 0.52), 높이 568. 안쪽 끝 X1241 = 구획선 |
| 뒤 여유 | X1241 ~ X1519 (278). 쓰지 않는다: 투입 칸을 여기 두면 쌓인 상자 위로 상자를 넘겨 올 수 없다 (장착면 620 - 적재 높이 568 = 52 mm) |
| 로봇 | 중심 X210 ~ X1210 (팀 레일 -0.49 ~ +0.51, 레일 0 = X700). 장착면 z 0.672 (바닥판 위 620) |
| **투입 칸 (유일한 버퍼)** | 입구 쪽 맨 앞줄 가운데. 칸 안쪽 X51 ~ X221 × y 0.195 ~ 0.365 (170 × 170), 칸막이 10 mm(바닥 표시) |
| 투입 칸 중심 | 월드 (0.136, 0.28, 0.052) = 로봇 좌표 `arrival` (-0.564, 0.000, -0.620) |
| 위에서 내려놓기 | 툴을 똑바로 아래로 향한 자세는 상자 윗면이 낮을 때만 된다(입구 쪽 기준 윗면 80 mm 50%, 120 mm 20%, 160 mm 7%, 200 mm 이상 0%). 그래서 입구 쪽 바닥 첫 층에만 쓴다(`rig/reach_top.npz`) |
| 팔이 닿는 곳 | 입구 쪽에서 밀어 넣기 자세가 되는 비율: X ≥ 0.70 m 100%, 0.46 ~ 0.64 71 ~ 92%, 0.22 ~ 0.40 12 ~ 30%, X < 0.20 0 ~ 8%. 로봇 중심이 X210 보다 앞으로 못 가서 입구 쪽 약 0.4 m 는 거의 못 쓴다. 계획은 닿는 자리만 쓴다 |
| **출력 좌표** | 로봇 좌표(m) = 월드 - `ROBOT_ORIGIN` (0.700, 0.280, 0.672). 축은 월드와 같다 |
| 컨테이너 좌표 (mm, `container_mm`) | 원점 = 적재 구역 안쪽 끝(X1241) 바닥 모서리. x = 입구 방향 = 월드 -x, y = 월드 -y, z = 위. 월드 = (1.241 - x/1000, 0.52 - y/1000, 0.052 + z/1000) |

## 4. 이동 하나 (`moves`의 한 항목)

| 순서 | 로봇 동작 | 필드 |
|---|---|---|
| 1 | 투입 칸 상자의 윗면을 흡착한다 | `from.grasp_m`, `from.grasp_normal` = (0, 0, 1) |
| 2 | 들어 올려, 흡착면이 입구(월드 -x)를 보게 돌린다 | `to.quat_wxyz` = 놓인 뒤 상자 자세 |
| 3 | 대기점으로 간다: 끝점에서 입구 쪽 40 mm, 끝점과 같은 높이 | `to.pre_insert_m` |
| 4 | +x로 40 mm 밀어 넣고 놓는다 | `to.grasp_m` = 흡착면 중심, `to.grasp_normal` = (-1, 0, 0) |

위에서 내려놓기 (`approach` = `top`, 큰 상자):

| 순서 | 로봇 동작 | 필드 |
|---|---|---|
| 1 | 투입 칸 상자의 윗면을 흡착한다 | `from.grasp_m` |
| 2 | 들어 올려 자리 위로 옮긴다. 흡착면은 위 그대로, 필요하면 세로축으로 90° 돌린다 | `to.quat_wxyz` |
| 3 | 대기점으로 간다: 끝점 40 mm 위 | `to.pre_insert_m` |
| 4 | 수직으로 40 mm 내려놓고 놓는다 | `to.grasp_m` = 윗면 중심, `to.grasp_normal` = (0, 0, 1) |

- `approach`: `front` = 입구 쪽에서 밀어 넣기(위 표), `top` = 위에서 내려놓기. CSV에도 같은 열이 있다.
- `kind`는 모두 `place`다(투입 칸 → 적재 구역). 칸 사이 옮기기는 없다.
- `box_id`: 적재 목록의 id. `feed_order` = 투입 칸에 넣을 순서 = 이동 순서. 앞 이동이 끝나야 다음 상자를 넣는다.
- `scene_before`: 이 이동 직전 장면이다. `placed` = `placements` 앞에서부터 실린 상자 수이고, `slots` = 투입 칸의 상자다.
- `ik`: 참고 해다(이 저장소 모델 기준). `pick` / `pre` / `insert` 자세마다 레일 위치, 베이스 x, 관절 6개(rad)가 있다.
  - `rail_team_m` = 팀 레일 좌표(베이스 x - 0.70). `rail_m`은 이 모델 레일(0 = 베이스 X210).
  - `pre`와 `insert`는 관절이 같고 레일만 40 mm 다르다.
- `kept`: 마감할 때 자리가 없어 투입 칸에 둔 채로 싣는 상자(드물다, 로봇 이동 없음).
- `not_loaded`: 자리가 없어 싣지 못한 상자. 목록이 공간보다 크면 먼저 내릴 지점 상자가 남는다.

## 5. 미리 확인한 것과 모션 담당 몫

계획 단계에서 이미 거른 것:
- 집기, 대기점, 밀어 넣기(또는 내려놓기) 세 자세의 IK와 충돌. 팔과 들고 가는 상자를 프레임, 바닥, 실린 상자에 대해 본다.
- 실린 상자가 팔꿈치나 아래팔에 닿는 자리. 팔 공간 표(`rig/arm_front.npz`)로 뺐다.
- 상자 안정성
  - 바닥의 90% 이상이 받쳐질 때만 놓고, 놓을 때마다 물리 시뮬레이션으로 확인한다.
  - 위치 ±6 mm, 치수 ±2 mm 오차와 마찰 0.35 로 64개 적재를 다시 쌓아도 넘어짐은 0이다 (가장 많이 밀린 상자 평균 8 mm).

모션 담당이 할 것:
- **자세 사이 경로**: 특히 집은 뒤 돌리기다. 이 팔 모델은 제자리에서 툴을 돌리면 관절이 이어지지 않는다. 빈 공간으로 들어 옮기며 돌려야 한다.
- **실제 로봇 모델로 다시 판단하기**: `rig/` 모델과 `ik`는 참고용이다. 특히 입구 쪽 자리(X < 0.5 m)는 팔을 많이 뻗어야 한다.
- **못 푸는 이동이 있을 때**: 이동 번호를 알려 주면 그 자리를 빼고 다시 계획한다.

## 6. 같이 정해야 할 가정

| 항목 | 지금 가정 | 바뀌면 |
|---|---|---|
| 툴 길이 | 80 mm (`rig/model.py` `TOOL_LENGTH`) | 표 2개를 다시 만든다: `uv run python -m rig.reach_table --tool 0.08`, `uv run python -m rig.arm_table` |
| 바닥판 두께 | 12 mm (도면 가정) → 바닥 z 0.052 | `pack_env.C_ORIGIN`, `rig/model.py` `FLOOR_TOP` 를 고치고 표를 다시 만든다 |
| 구획선 X1241 | 바닥 선이고 벽(턱)이 없다. 시뮬레이션은 안쪽 끝에 벽이 있다고 본다 | 안쪽 끝 상자를 밀 때 밀려나지 않게 40 mm 만 민다 |
| 투입 칸 | 입구 쪽 맨 앞줄 가운데, 칸막이는 바닥 표시 | 위치를 바꾸면 알려 달라 |
| 밀어 넣는 높이 | 끝점과 같은 높이라서 아래 상자 위를 40 mm 미끄러진다 | 1~2 mm 띄워 밀고 내려놓기를 권한다 (끌림은 시험하지 않았다) |
| 투입 | 계획의 `feed_order` 순서대로 투입 칸에 넣는다 | 순서를 못 지키면 다시 계획해야 한다 |

## 7. 성능

같은 64개 작업, 물리 시뮬레이션과 팔 검사 켬. 적재율 = 적재 구역 전체 부피(1200 × 480 × 568) 대비.

| 큰 상자 (`--mode big`, 최종) | 모델 그대로 1번 | 16번 계획 중 최선 (기본) |
|---|---|---|
| 목록이 공간보다 클 때 (공간의 1.2~1.4배): 적재율 | 48.2% (89개) | **48.6% (90개)** |
| 다 들어갈 크기 (공간의 36~44%): 빠짐없이 다 실은 작업 | 95.3% | **98.4%** |

- 하차 순서 위반, 하차 재작업, 팔 때문에 막힌 작업은 모두 0이다. 로봇 이동은 상자 1개당 1번이다.
- 위에서 내려놓기는 공간보다 큰 목록에서 작업당 약 2개(최대 3개) 쓴다. 빼면 48.3% / 96.9% 였다.
- 실물 오차 시험(위치 ±6 mm, 치수 ±2 mm, 마찰 0.35 로 다시 쌓기): 넘어진 적재 0/64, 가장 많이 밀린 상자 평균 7.7 mm.
- 입구 쪽 약 0.4 m 는 바닥 첫 층 말고는 팔이 거의 못 닿아서 쓰지 못한다 (3절). 이전 배치(적재 X320 ~ 1520, pack_env 원래 값)에서는 약 62% 였다.
- 기본 상자(`--mode stable`, 밀어 넣기만): 48.5% / 100% (같은 조건, 16번 중 최선).
- 예시 `examples/list/`
  - 큰 상자 80개 (리그 부피의 40%): 80개 모두 80번 이동으로 싣는다. `check_plan.py` 로 다시 검사해도 모두 통과한다.
  - 기본 상자 115개: 모두 115번 이동, 모두 통과.
  - 영상 `list_big_load_unload.mp4` (적재 다음 하차).
