# 모션플래닝: 정해진 네 단계로 옮기기

## 결론

상자 하나를 옮기는 동작을 **항상 같은 네 단계**로 고정한다. 단계마다 바뀌는 입력만 받고, 경로를 그때그때 탐색하지 않는다.

| 단계 | 내용 | 바뀌는 입력 |
|---|---|---|
| 1. 집기 | 투입 위치로 가서 윗면을 흡착 | 상자 높이 (+ 카메라가 잰 작은 오차) |
| 2. 이송 자세 | 들어올리기 → 공구 세우기 → 돌리기 → 팔을 놓는 자세로 | 놓을 자리의 y, z, 상자 방향 |
| 3. 레일 이동 | 팔은 고정, 레일만 이동 | 놓을 자리의 x |
| 4. 놓기 | 내리기 → 밀어 넣기 → 흡착 끔 → 온 길로 복귀 | 없음 (2에서 이미 맞춤) |

- **어디에 놓을지**는 Packing Model(`manibox_packing_handoff`)이 정한다.
- **어떻게 옮길지**는 위 네 단계다. 역기구학과 충돌 검사는 `../mp/stacking.py` (`sim_final` 의 `Stacker` 를 옮긴 것)를 쓴다.
- 지금의 `Stacker.plan` 은 상자마다 경로를 탐색한다. 탐색은 실패할 수 있고(시험 23개 중 5개), 결과가 관절값 목록이라 "이 상황에서는 이렇게"를 고칠 곳이 없다. 그래서 탐색 대신 정해진 순서로 바꾼다.

## 왜 이렇게 나눌 수 있나

레일이 x 방향이다. 팔은 놓을 자리의 **y, z, 방향만 맞춘 자세**를 잡고, x 는 레일이 전부 맡는다.
그러면 팔 자세는 (y, z, 방향) 조합마다 하나면 된다.

handoff 예시 계획(`moves_big_104.json`, 놓기 102개)에서 확인한 것:

| 항목 | 값 |
|---|---|
| 놓는 방식 | 102개 모두 흡착면이 문 쪽(−x)을 보는 옆면 방식 |
| x | 50가지 (사실상 연속) → 레일이 맡는다 |
| y | 12가지 |
| z | 6단 |
| 상자가 놓인 모양 (x·y·z 길이) | 7가지 |

## 단계별 내용

### 1. 집기

- 투입 위치는 항상 같다. 상자 높이만큼 내려가는 깊이가 달라진다.
- 경로는 **상자 종류 × 잡는 방향**마다 한 번 계산해 저장하고 매번 같은 것을 쓴다.
- 카메라가 잰 오차(dx, dy)는 마지막 닿는 점만 옮긴다. 오차가 크면 집지 않고 멈춘다.

### 2. 이송 자세

1. 5 mm 띄운다.
2. 수직으로 들어올린다.
3. 공구를 5° 씩 수평(+x)으로 세운다. 흡착면이 문 쪽을 보게 된다.
4. 공구축 둘레로 돌려 상자의 세울 변을 맞춘다.
5. 팔을 **놓는 자세**로 옮긴다: 놓을 자리의 y, z 에 맞춘 자세에서 높이만 이송 높이로 올린 것.

1 ~ 4 는 투입 구역 안에서만 일어난다. 그 구역을 비워 두면 쌓인 상자와 무관해서 1번처럼 저장해 둔 경로를 쓴다.
5 의 팔 자세는 **(y, z, 방향) 표**에서 찾는다. 표는 미리 전부 계산해 둔다.

### 3. 레일 이동

- 레일 목표 = 놓을 자리의 x − (팔 자세에서 공구 끝이 베이스보다 앞에 나온 거리) − 접근 거리 15 mm.
- 팔은 움직이지 않는다. 쌓인 상자 위(공구 끝 최고 0.47 m)로 지나간다.

### 4. 놓기

1. 자리보다 15 mm 문 쪽에서 수직으로 내려와 받침 위 5 mm 에서 멈춘다.
2. +x 로 15 mm 민다 (레일로 할 수 있다).
3. 5 mm 내려 얹고 흡착을 끈다.
4. 온 길을 거꾸로 빈손으로 돌아간다.

## 실패를 없애는 방법

| 단계 | 쌓인 상자의 영향 | 보장하는 방법 |
|---|---|---|
| 1, 2 (세우기까지) | 없음 (투입 구역 안) | 한 번 검증한 경로를 그대로 쓴다 |
| 2 (팔 자세) | 없음 | 표에 있는 (y, z, 방향)만 허용. 없는 자리는 Packing Model 에서 `reject()` |
| 3, 4 | 있음 | 실행 전에 전체 목록을 시뮬레이션에서 끝까지 돌린다. 막히는 자리는 그때 `reject()` |

실물로 넘어가는 목록은 전부 통과한 것뿐이다. 계획 실패는 실행 전에 걸러진다.
흡착을 놓치는 것 같은 하드웨어 문제는 이 방법으로 막지 못한다.

지켜야 하는 전제:
- **투입 구역(월드 x < 0.70 m)에는 싣지 않는다.** 깨지면 1, 2 를 고정할 수 없다. handoff 정책은 x = 0.5 m 까지 채우려 하므로 적재 깊이를 줄여야 한다.
- **투입 위치는 중심선(월드 y = 0.28 m) 위의 한 점**이다. 모서리 지그로 상자를 같은 자리에 놓게 한다.

## 편집하는 곳

"이런 상황이면 이렇게 움직인다"는 규칙 파일 하나에 모은다. 위에서부터 처음 맞는 규칙을 쓴다.

| 고칠 수 있는 값 | 지금 값 |
|---|---|
| 집은 뒤 띄우는 높이 | 5 mm |
| 세우는 각도 단계 | 5° |
| 잡는 방향 순서 | 카메라 받침이 위로 가는 방향부터 |
| 이송 높이 | 공구 끝 0.47 m |
| 자리 앞 접근 거리 / 띄운 높이 | 15 mm / 5 mm |
| 흡착 위치 오프셋 | 0, ±4 mm |

조건으로 쓸 수 있는 값: 상자 종류와 높이, 눕는 방향, 놓을 자리의 높이 단, 벽에 붙는지, 이웃 상자 유무.

규칙을 고칠 때마다 기준 계획(예시 102개)을 전부 다시 돌려 통과 수와 달라진 상자를 본다.

## 좌표

- 월드: 프레임 모서리 바닥이 원점. x = 레일 방향(문 → 정면 벽), z = 위.
- 로봇 좌표 = 월드 − (0.700, 0.280, 0.672). `moves.json` 의 `to.center_m`, `to.size_xyz_m` 가 이 좌표다.
- 레일 0 일 때 베이스가 월드 x = 0.7 m. 범위 −0.49 ~ +0.51 m. (`handoff 레일 − 0.5`)
- 공구: 플랜지에서 흡착컵 끝까지 147.5 mm (컵 길이 25 mm 는 가정값).

## 만드는 순서

1. `mp/sequence.py`: 네 단계를 함수 네 개로. 역기구학·충돌 검사는 `stacking.py` 의 것을 부른다.
2. 집기 경로(상자 종류 × 잡는 방향)와 팔 자세 표(y, z, 방향)를 미리 계산해 파일로 저장.
3. 규칙 파일과 전체 검사 스크립트.
4. 예시 102개를 `mp/` 작업 형식으로 바꿔 전부 돌린다. `BOXES` 에 없는 160 × 160 × 80 상자를 추가해야 한다.
5. 통과하지 못한 자리를 규칙으로 해결하거나 `reject()` 대상으로 정한다.
6. 사전 검증(전체 계획 → `reject()`)을 Packing Model 과 잇는다.

## 아직 확인하지 않은 것

- **"(y, z, 방향)만으로 팔 자세가 정해진다"** 는 가정이다. 4번에서 102개를 돌려 봐야 확인된다. 프레임 기둥이나 벽 근처에서는 x 에 따라 달라질 수 있다.
- 실물 치수: 공구 길이, 레일 0 위치, 레일 범위, 투입 위치.
- 버퍼 칸 이동(`stage`): 예시 103개 이동 중 1개다. 이 방식에는 넣지 않았다.
